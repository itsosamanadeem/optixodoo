Operation and Verification

Backup process

  1. The scheduled action Backup : Daily Database Backup invokes the module once per day for configurations with Daily frequency. The actual execution time must be checked in the live scheduled action; it is not shown in the screenshot.
  2. The module creates a ZIP archive containing the PostgreSQL database dump, a manifest, and the database filestore when that filestore exists.
  3. The archive is uploaded to /home/optix/backup on 192.168.171.83:1051 using the SFTP account optix.
  4. After upload, automated cleanup removes remote files whose modification age is at least two whole days. The module then attempts to send a success notification; exceptions trigger an attempted failure notification.

Archive names follow Live_30_May_2026_YYYY-MM-DD_HH-MM-SS.zip. The timestamp in the filename is generated in UTC. Retention is age based; it does not guarantee that exactly two backup files remain.

Administrator checklist

  1. Open the Live DB Backup record under Settings / Technical / Automatic Database Backup and verify the values on page 1. The screenshot shows an out-of-date page notice; save any intended edits and refresh before verifying the current record.
  2. Use Test Connection to check SFTP login. This checks authentication and SFTP access, but does not verify that the destination directory is writable or that a database archive can be generated.
  3. Check that the daily scheduled action is active and review its next execution time. After a scheduled run, verify a recent ZIP exists in the remote directory and has a plausible size.
  4. Confirm notification delivery to Administrator and check the configured email address and outgoing mail setup if messages are absent.
  5. Periodically restore a downloaded backup into an isolated test database and verify database records and attachments.

Retention and troubleshooting

Use a dedicated backup directory: the SFTP cleanup code evaluates all entries in the configured directory without filtering by database name or filename extension. Do not mix unrelated files into this path.

For connection failures, check network reachability, port 1051 and credentials. For upload failures, check directory permissions and free space. For dump failures, review Odoo logs and PostgreSQL dump access. For missing attachments, verify the source filestore and the restored archive.
